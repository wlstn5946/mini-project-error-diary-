# PRD: 에러 해결 일기

> 이 문서는 "큰 틀"만 담는다. 세부 기능은 개발하면서 채운다.
> 결정의 이유는 DECISIONS_N에 적고, 여기서는 D-ID만 참조한다.

## 1. 제품 개요
- **한 줄 설명**: 에러 메시지를 입력하면 내가 이전에 해결한 기록을 먼저 찾아 보여주고, 기록이 없으면 AI(Gemini)가 해결 방법을 제안하는 에러 해결 기록 앱
- **해결하려는 문제**: 이전에 해결한 에러의 기록이 남지 않아, 같은 에러를 다시 만나면 처음부터 다시 찾아야 한다
- **사용자**: 1인 사용, 로그인 없음 (D-002)
- 세부 사용자 상황은 [결정 필요]

## 2. 목표와 성공 기준
- 같은 에러를 다시 입력하면 이전 해결 기록을 먼저 보여준다
- 기록이 없을 때 AI 제안을 받아 시도 → 해결까지 기록할 수 있다
- 해결된 에러마다 "내 한 줄 정리"가 남는다
- 정량 지표는 [결정 필요] (Q-006)

## 3. 핵심 흐름
에러 입력 → 기존 기록 확인 → 없으면 AI 제안 → 시도 기록 → 해결 → 내 한 줄 정리

(화면 상세는 SCREEN-SPEC_N.md에서 다룬다)

## 4. 범위
- **만들 것 (Now)**: R-001 ~ R-005
- **나중에 (Later)**: 복습 퀴즈 (D-004), 추천 태그 (D-023, 후보), 시도 출처 표시 (D-032, 후보), 태그 합치기 (D-049), 여러 개 한 번에 삭제·삭제 되돌리기 (D-043), 시도 내용 수정 (D-047)
- **안 만들 것**: 로그인 (D-002), 학습 기록 기능 (D-003)

## 6. 규칙
- **확정**
  - 시리즈와 태그는 에러를 입력할 때 지정한다 (D-006)
  - 새 시리즈는 따로 만들지 않고 에러를 저장할 때 함께 만든다 (D-011)
  - 새 태그도 따로 만들지 않고 에러를 저장할 때 함께 만든다 (D-020)
  - 태그는 에러 하나당 최대 5개 (D-022)
  - 에러는 새 에러로 확정되는 순간(AI에게 묻기 직전) 미해결로 저장한다 (D-025)
  - "해결됨"으로 기록하면 내 한 줄 정리가 필수이고, 시도 저장과 해결 처리가 함께 이뤄진다 (D-026)
  - "해결 안 됨"·"일부 해결"이면 실패 시도를 저장하고 AI에게 다음 방법을 다시 묻는다. 에러는 미해결로 남는다 (D-027, D-029)
  - 해결된 에러에는 시도를 더 추가하지 않는다 (D-032)
  - 비슷한 기록은 해결된 기록 중 유사도 60% 이상만, 유사도 높은 순으로 보여준다. 위 2건은 칸에 보이고 나머지는 스크롤로 본다 (D-040)
  - 비슷한 기록의 "이 방법 적용"은 새 기록을 해결됨으로 저장하고 내 기록으로 이동한다 (D-041)
  - 기록 삭제는 확인 후 완전 삭제이고, 그 기록의 시도·태그 연결도 함께 지워진다. 쓰이지 않게 된 태그·시리즈는 남는다 (D-043, D-044, D-046)
  - 기록 수정은 상황·시리즈·태그만 가능하고 에러 메시지는 바꾸지 않는다 (D-047, D-048)
  - 태그·시리즈 이름을 바꿀 때 같은 이름이 있으면 막고, 쓰이는 태그·시리즈도 지울 수 있다(기록은 남는다) (D-049, D-050)
  - 시리즈 안 순서는 시리즈에 넣은 순서가 기본이고 바꿀 수 있다. 시리즈가 없는 기록은 시리즈별 보기에 나오지 않는다 (D-051, D-053)

## 7. MVP 완료 조건
- 입력 → 검색 → AI 제안 → 시도 → 해결이 끊김 없이 동작한다

## 8. 제약 사항
- **기술 스택**: FastAPI + React(Vite, TypeScript) + SQLite + Gemini API
- **로그인 없음**: 1인 사용 (D-002)
