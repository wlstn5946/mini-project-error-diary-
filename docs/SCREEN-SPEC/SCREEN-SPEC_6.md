# SCREEN-SPEC: 에러 해결 일기 (v6)

## 1. 문서 설명
- 화면 흐름, 예시 이미지, 화면 상태를 담는 문서다. 기능 설명은 PRD에 있으므로 여기서는 R-ID로만 가리킨다.
- **이번 버전(v6)의 범위는 v5에 "내 기록 정리"(S-002 시리즈별 보기·관리 모달, S-003 수정·삭제)를 더한 것이다.** v5까지의 S-002 목록·S-003 상세는 구현됨, v6에서 더한 부분은 모두 미구현이다.
- 참고 시안: `에러해결창_예시.png`, `내기록창_예시.png` (저장소 루트). 에러 해결 화면의 시리즈·태그 영역은 에러해결창 ①, 시도 기록·해결 완료는 ②③, 내 기록 목록·필터는 내기록창 ①②, 상세는 내기록창 ④를 참고하고, 나머지는 레이아웃만 참고한다.
- 시안 속 기능의 채택 여부는 Q-004에서 정하며, 이 문서에서 결정하지 않는다.
- 색상·간격 등 디자인 수치는 적지 않고 "시안 참고"로 대신한다.

- 강조 모양은 시안을 참고한다.

## 4. 화면별 명세

### S-001 에러 해결 (`/solve`)
| 구분 | 내용 |
|------|------|
| 이번 범위 | 본문 제목 "에러 해결" 표시, 사이드바의 "에러 해결" 메뉴 강조, 탭 2개("에러 입력" / "AI 분석"), 시리즈 선택, 태그 입력, 에러 메시지, 상황 (선택) 입력, 비슷한 기존 기록, 흐름과 시도 기록·해결 완료 영역(아래) |
| 이후 작성 | 그 밖의 영역은 시안 참고, Q-004 결정 후 작성 (관련: R-001 ~ R-004) |

#### 화면 구성 (탭)
- "에러 입력" 탭: 시리즈 → 태그 → 에러 메시지 → 상황 (선택) → "해결 방법 찾기". `frontend/src/pages/SolvePage.tsx`
- "AI 분석" 탭: 저장된 에러 메시지, 저장한 시도 목록("시도 N · 결과" + 무엇을 했나요), AI 제안 카드, 시도 기록 영역 또는 해결 완료 영역. 탭 옆 배지는 "분석 중…" / "완료"
- 탭을 바꿔도 입력·선택한 값은 그대로 남는다.

#### 에러 저장 후 잠금 (D-034)
- A-002로 저장되면 "에러 입력" 탭의 에러 메시지·상황·시리즈·태그를 잠그고 "해결 방법 찾기" 버튼을 숨긴다.
- 위에 "저장된 에러예요. 내용을 바꾸려면 새 에러로 입력해 주세요." 안내와 "새 에러 입력" 버튼을 보여준다.
- "새 에러 입력"은 모든 입력과 결과를 비우고 "에러 입력" 탭으로 돌아간다. 시리즈·태그 목록도 다시 불러와서 방금 만든 시리즈·태그가 보인다.

#### 화면 흐름 (D-025, D-027)
1. 에러 메시지·시리즈·태그를 입력하고 "해결 방법 찾기"를 누른다.
2. 비슷한 기존 기록을 확인한다 (A-003, D-040). 저장하기 전에 검색만 한다.
   - 1건 이상이면 "에러 입력" 탭의 버튼 아래에 비슷한 기록 영역(아래)을 보여준다. "해당 없음 → AI에게 묻기"를 누르면 3으로 간다.
   - 영역에서 "같은 에러예요, 이 방법 적용"을 누르면 새 기록을 해결됨으로 저장하고 "내 기록"(`/records`)으로 이동한다 (D-041). 3~5는 건너뛴다.
   - 0건이면 영역 없이 바로 3으로 간다.
   - 검색이 실패하면(서버 꺼짐 등) "비슷한 기록을 확인하지 못해 바로 AI에게 물었어요." 안내를 보여주고 바로 3으로 간다.
3. A-002로 에러를 미해결 상태로 저장한다. 성공하면 A-005로 AI 제안을 받는다.
4. AI 제안 아래에서 "시도 N 기록하기"로 시도를 기록한다 (아래 시도 기록 영역).
5. "해결됨"이면 해결 완료 영역으로, "해결 안 됨"·"일부 해결"이면 새 AI 제안과 "시도 N+1 기록하기"로 돌아간다.

- A-002 저장이 실패하면 AI로 넘어가지 않고 입력값을 그대로 둔 채 안내("… 입력한 내용은 그대로 있어요.")를 보여준다. "해결 방법 찾기"를 다시 누르면 다시 시도한다. 시도는 `error_id`가 있어야 저장되기 때문이다.
- 새 시리즈 이름이 비었거나 중복이면 "해결 방법 찾기"를 막고 "시리즈 이름을 확인해 주세요." 안내를 보여준다.
- 저장 중에는 버튼이 "저장 중…"으로 바뀌고 다시 누를 수 없다.

**동작 규칙**
- 에러 메시지를 고치면 보이던 비슷한 기록 영역은 사라진다. 다시 "해결 방법 찾기"를 눌러 검색한다.
- "이 방법 적용"을 누르면 에러 저장(A-002)과 해결됨 처리(A-006, 시도 1개의 `action`은 "기존 기록 #N의 해결 방법 적용", 한 줄 정리는 고른 기록의 것을 복사)를 이어서 한 뒤 `/records`로 이동한다. 이동하면 내 기록(S-002) 맨 위에 새 기록이 "해결"로 보인다. 한 줄 정리는 나중에 수정할 수 있다(A-007 이후).
- 적용 중에는 두 버튼을 비활성하고 누른 카드 버튼이 "적용 중…"으로 바뀐다. 빠르게 두 번 눌러도 한 번만 처리한다.
- 에러 저장은 됐는데 해결됨 처리가 실패하면 영역 안에 "… 입력한 내용은 그대로 있어요." 안내를 보여준다. 입력은 잠기고(D-034), 다시 누르면 이미 저장한 에러에 이어서 처리한다. 이미 해결로 저장된 경우(409)는 성공으로 보고 이동한다.

**필터 규칙**

- 필터 값은 URL 쿼리에 둔다. 상세에 갔다가 뒤로 오거나, 같은 주소로 다시 열면 필터가 그대로다 (D-036).

- 태그를 여러 개 고르면 고른 태그를 모두 가진 기록만 보인다.
- 필터를 바꿔도 방문 기록이 쌓이지 않는다(주소를 바꿔 끼움). 브라우저 뒤로 가기는 내 기록에 들어오기 전 화면으로 간다.

#### 탭: 날짜별 / 시리즈별 (D-042, 미구현)
- 제목 아래에 탭 2개 "날짜별"(기본) / "시리즈별"을 둔다. 고른 탭은 주소 쿼리 `?view=series`에 둔다(없으면 날짜별). 주소로 열거나 상세에 갔다 뒤로 와도 같은 탭이 남는다.
- "날짜별" 탭은 위에서 설명한 목록과 필터 그대로다.
- "시리즈별" 탭에서는 검색창과 상태·태그 칩을 숨긴다. 순서 바꾸기(A-014)가 그 시리즈의 에러 **전체**를 대상으로 하므로, 필터로 일부만 보이면 ▲▼의 뜻이 모호해지기 때문이다.
- 제목 줄 오른쪽에 "⚙ 관리" 버튼이 있다. 두 탭에서 모두 보인다. 메뉴는 늘리지 않는다(D-005).

#### 시리즈별 보기 (D-042, D-051, D-053, 미구현)
1. **시리즈 카드 목록** (`?view=series`): 시리즈마다 카드 하나 — 이름, 설명(있으면), "에러 N개"(`error_count`, A-004). 최근 만든 시리즈가 위. 카드를 누르면 그 시리즈를 연다. 시리즈가 하나도 없으면 "아직 시리즈가 없어요. 에러를 입력할 때 시리즈를 만들 수 있어요."
2. **고른 시리즈** (`?view=series&series_id=N`):
   - "← 시리즈 목록", 시리즈 이름·설명, "이름·설명 수정" 버튼
   - 에러 목록(A-008 `series_id`, 시리즈 안 순서): 항목마다 순서 번호(목록 위치 1부터, D-051), 상태 배지, 제목(첫 줄), 시도 N회, 태그, ▲ ▼ 버튼. 항목을 누르면 S-003으로 간다(▲▼는 눌러도 이동하지 않는다)
   - 시리즈가 없는 에러는 시리즈별 탭에 나오지 않는다 (D-053)
3. **순서 바꾸기**: ▲는 한 칸 위, ▼는 한 칸 아래로 옮긴다. 첫 항목의 ▲, 마지막 항목의 ▼는 비활성이다. 누르면 화면을 먼저 바꾸고 전체 순서를 A-014로 보낸다. 저장 중에는 ▲▼를 모두 비활성으로 두고, 실패하면 원래 순서로 되돌린 뒤 "순서를 바꾸지 못했어요. 다시 시도해 주세요."를 보여준다.
4. **이름·설명 수정**: 이름 입력칸과 설명 입력칸(설명은 비워도 됨)이 열리고 "저장" / "취소"가 있다. 저장하면 A-013 `PATCH`. 같은 이름이 이미 있으면(409) "이미 있는 이름이에요."를 보여주고 입력값은 그대로 둔다. 이름이 비면 저장 버튼을 막는다 (D-054).

#### 관리 모달 (D-042, D-049, D-050)
- "⚙ 관리"를 누르면 모달이 열린다. 닫기(×, 바깥 클릭, Esc)를 누르면 닫히고, 닫을 때 바뀐 게 있으면 목록과 태그 칩을 다시 불러온다. 지운 태그가 내 기록의 태그 필터(주소의 `tag_id`)에 걸려 있었다면 주소의 필터에서도 뺀다(없는 태그로 거르면 항상 빈 결과라서).
- 구성: "태그" 구역(태그마다 이름, "N개 기록", "이름 변경", "삭제")과 "시리즈" 구역(시리즈마다 이름, "N개 기록", "이름·설명 수정", "삭제"). 개수는 `error_count`(A-004)다. 태그는 이름순, 시리즈는 최근 만든 순(A-004와 같다).
- **이름 변경**: 그 줄이 입력칸 + "저장" / "취소"로 바뀐다(시리즈는 설명 입력칸도). 저장하면 A-012 / A-013 `PATCH`. 같은 이름이 이미 있으면(409) "이미 있는 이름이에요."를 그 줄에 보여주고 입력값은 그대로 둔다. 같은 태그의 대소문자만 바꾸는 것은 허용한다 (D-049). 태그는 저장하면 서버의 이름순으로 다시 받아 정렬이 바뀔 수 있다. 입력 중 Esc는 모달이 아니라 그 줄의 수정만 닫는다. 이름 입력칸에 글자 수 제한은 두지 않는다(최대 길이는 Later).
- **삭제**: 확인 창을 띄운다.
  - 태그: "#Python 태그를 지울까요? 3개 기록에서 태그가 빠져요. 기록은 지워지지 않아요."
  - 시리즈: "'개발 환경' 시리즈를 지울까요? 3개 기록에서 시리즈가 비워져요. 기록은 지워지지 않아요."
  - 개수가 0이면 "빠져요/비워져요" 문장 대신 "되돌릴 수 없어요."만 보여준다. 확인하면 A-012 / A-013 `DELETE`. 쓰이는 태그·시리즈도 지울 수 있다 (D-050).
- 태그·시리즈를 새로 만드는 곳은 여기에 없다. 에러를 입력할 때 만든다 (D-011, D-020).

6. 내 한 줄 정리 (해결된 에러만)

#### 수정 (D-047, D-048, 미구현)
- 상세 제목 줄 아래에 "태그·시리즈·상황 수정"과 "삭제" 버튼이 있다.
- "태그·시리즈·상황 수정"을 누르면 같은 화면이 **편집 모드**로 바뀐다. 시리즈 선택(`SeriesSelect`), 태그 입력(`TagInput`), 상황 입력칸이 현재 값으로 채워져 나타나고 "저장" / "취소"가 있다. 두 컴포넌트는 에러 해결 화면과 같은 것을 재사용하고, 현재 값을 채우는 선택 props만 더한다(기존 사용법은 그대로).
- 에러 메시지, 상태, 시도 기록, 내 한 줄 정리는 편집 모드에서도 읽기 전용이다. 에러 메시지는 비슷한 기록 검색의 기준이라 수정하지 않는다 (D-047). 한 줄 정리 수정은 A-007(이후 단계)이 맡는다.
- 규칙은 에러 등록과 같다: 새 시리즈는 이름만 입력하면 저장할 때 만들어지고, 같은 이름이면 기존 시리즈를 쓴다. 태그는 최대 5개, 정규화·기존 표기로 합침, 새 태그는 저장할 때 만들어진다 (D-048). 새 시리즈 이름이 비었거나 중복이면 저장 버튼을 막는다(`SeriesSelect`가 null을 넘기는 상태).
- 저장하면 A-010 `PATCH`로 바뀐 필드만 보내고, 성공하면 편집 모드를 닫고 바뀐 내용을 보여준다. 다른 시리즈로 옮기면 서버가 그 시리즈의 마지막 순서로 넣는다.
- "취소"는 바꾼 것을 버리고 읽기 모드로 돌아간다. 아무것도 바꾸지 않고 저장해도 된다.

#### 삭제 (D-043, D-044)
- "삭제"를 누르면 확인 창이 뜬다: "이 기록을 지울까요?" + 지워지는 것만 이름을 붙인 안내 — "시도 2개와 한 줄 정리도 함께 지워지고 되돌릴 수 없어요."(시도가 없으면 "시도" 부분, 한 줄 정리가 없으면 "한 줄 정리" 부분을 뺀다. 둘 다 없으면 "되돌릴 수 없어요.") + "취소" / "삭제". 처음 포커스는 "취소"에 있고 Esc로도 닫힌다. 확인 창은 브라우저 기본 모달(`<dialog>`)이다.
- "삭제"를 누르면 A-011 `DELETE`. 성공하면 들어온 목록 주소(`backTo`, 없으면 `/records`)로 이동한다. 실패하면 확인 창을 닫지 않고 안내를 보여주며 확인 버튼이 "다시 시도"로 바뀐다.
- 쓰이지 않게 된 태그·시리즈는 남는다. 지우려면 "⚙ 관리"에서 한다 (D-046).

## 5. 화면 이동 규칙

| 상황 | 동작 |
|------|------|
| 메뉴 클릭 | 해당 화면 경로로 이동하고, 메뉴 강조를 그 화면으로 바꾼다 |
| 현재 화면의 메뉴 다시 클릭 | 화면을 그대로 둔다 |
| 처음 접속 (`/`) | S-001 에러 해결(`/solve`)로 이동한다 |
| 없는 경로 접근 | S-004 "찾을 수 없음" 안내를 보여준다. 사용자는 사이드바 메뉴로 다른 화면에 갈 수 있다 |
| 내 기록 항목 클릭 | S-003 `/records/:id`로 이동한다. "내 기록" 메뉴 강조는 그대로다 |
| 상세에서 "← 내 기록" / 브라우저 뒤로 가기 | 들어오기 전 목록 URL(필터 포함)로 돌아간다 |
| 상세에서 삭제 성공 | 들어온 목록 URL(필터·탭 포함)로 이동한다. 삭제한 상세 주소는 방문 기록에서 바꿔 끼운다 |
| "시리즈별" 탭 / 시리즈 카드 | `?view=series` / `?view=series&series_id=N`로 바뀐다. "← 시리즈 목록"은 `?view=series`로 돌아간다 |
| 시리즈별 보기에서 항목 클릭 | S-003으로 간다. "← 내 기록"은 그 시리즈를 연 목록 URL로 돌아온다 |
