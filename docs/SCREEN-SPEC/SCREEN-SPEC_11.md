# SCREEN-SPEC: 에러 해결 일기 (v11)

## 1. 문서 설명
- 화면 흐름, 예시 이미지, 화면 상태를 담는 문서다. 기능 설명은 PRD에 있으므로 여기서는 R-ID로만 가리킨다.
- **v11은 재사용 기록을 원본과 연결해 보여주는 화면 규칙(D-080, D-081)을 더한 것이다: S-002 날짜별·태그별 탭의 원본 아래 접기와 "재사용 N" 배지·"원본 #N" 링크, 시리즈별 탭의 "재사용" 배지, S-003 타임라인의 재사용 기록과 원본 링크, S-001 태그 입력의 "비슷한 기록의 태그" 추천 칩. 구현과 타입·빌드 확인을 마쳤고 눈으로 보는 확인은 6절 v11 항목에 남아 있다.**
- **v10은 S-003에 "내보내기"(Markdown 내려받기, PDF로 인쇄)를 더한 것이다(D-079). 구현과 브라우저 확인을 마쳤고, PDF 기본 파일 이름의 브라우저별 결과만 6절 v10 항목에 남아 있다.**
- **v9는 S-001에 "이어서 해결하기"(`/solve?retry={id}`, 진입 탭 분기·잠금 표시·이전 시도·예외 상태)를, S-003에 "이어서 해결하기" 버튼을 더하고, S-001 상태를 "뼈대"에서 "구현됨"으로 고친 것이다(D-075 ~ D-077).**
- **v8은 S-001 에러 해결 화면을 3단계 탭(에러 입력 / AI 제안 → 시도 기록 / 결과)으로 바꾸고, 저장을 마지막 "기록 저장" 한 번으로 미루며(D-064, D-065), 결과 탭과 S-003에 AI 피드백·한 줄 정리 수정을 더한 것이다(D-066 ~ D-070).**
- **v7은 v6의 "⚙ 관리" 모달을 없애고 태그·시리즈 관리를 탭별로 나눈 것이다(S-002, D-061 ~ D-063). 구현은 됐고 브라우저 확인은 6절 v7 항목에 남아 있다.**
- **이번 버전(v6)의 범위는 v5에 "내 기록 정리"(S-002 시리즈별 보기·관리 모달, S-003 수정·삭제)를 더한 것이다.** v5까지의 S-002 목록·S-003 상세와 v6에서 더한 부분은 모두 구현됨이다.
- 참고 시안: `에러해결창_예시.png`, `내기록창_예시.png` (저장소 루트). 에러 해결 화면의 시리즈·태그 영역은 에러해결창 ①, 시도 기록·해결 완료는 ②③, 내 기록 목록·필터는 내기록창 ①②, 상세는 내기록창 ④를 참고하고, 나머지는 레이아웃만 참고한다.

- 색상·간격 등 디자인 수치는 적지 않고 "시안 참고"로 대신한다.

## 3. 공통 레이아웃
모든 화면은 아래 구성을 같이 쓴다.

| 영역 | 이번 범위 | 이후 작성 |
|------|-----------|-----------|
| 왼쪽 사이드바 | 앱 이름 "🛠 에러 일기", 그 아래 메뉴 2개 (에러 해결 → 내 기록 순서, D-005), 그 아래 "내 기록 통계" 대시보드 4칸 (아래 "사이드바 통계", D-074) | - |
| 오른쪽 본문 | 현재 화면의 제목 | 화면별 내용 (4절) |

**사이드바 통계** (시안 내기록창_예시.png의 "에러 기록 N개 · 해결 · 미해결 · 재사용 해결", D-074)
- 담당 공용 (`frontend/src/components/SidebarStats.tsx`, 스타일 `frontend/src/index.css`). API 호출은 `features/records/errorsApi.ts`의 `getErrorStats()` (A-017)
- 메뉴 아래에 **한 칸에 한 줄씩 4칸**을 세로로 둔다. 칸마다 굵은 글씨(800)와 색 테두리(2px)로 구분한다.

| 칸 | 값 | 누르면 |
|----|----|--------|
| 에러 기록 | 전체 기록 수 "N개" (회색 테두리) | `/records` (전체, 필터 없음) |
| 해결 | 해결된 기록 수 "N개" (초록 테두리) | `/records?status=resolved` |
| 미해결 | 미해결 기록 수 "N개" (빨간 테두리). 14일 이상 지난 미해결 기록이 있으면 글자 앞에 깜빡이는 빨간 불 | `/records?status=unresolved` |
| 재사용 해결 | "이 방법 적용"으로 저장한 해결 기록 수 "N회" (파란 점선 테두리) | 이동 없음. 표시 칸이다 (모아 보는 필터가 없음, 이후 단계) |

- **버튼 모양**: 앞 3칸은 글씨 링크가 아니라 3D 버튼처럼 보인다. 아래에 같은 색 그림자(3px)가 있고, 마우스를 올리면 연한 색으로 바뀌며, **누르는 동안 3px 내려앉고 그림자가 사라진다**. 키보드 포커스에는 파란 윤곽선이 보인다. 움직임 줄이기 설정이면 애니메이션을 끈다. 표시 칸(재사용 해결)은 그림자·눌림 없이 점선이라 눌리지 않는 것을 알 수 있다.
- **빨간 불** (D-078): 미해결 칸의 글자 앞에 깜빡이는 작은 빨간 원이 보이면 "등록한 지 14일 이상 지난 미해결 기록(오래된 기록)이 있다"는 뜻이다. `GET /api/errors/stats`의 `stale_unresolved`가 1 이상일 때만 켜지고, 0이거나 숫자를 못 불러오면 보이지 않는다. 칸 이동 주소는 그대로 `/records?status=unresolved`다(오래된 기록만 보려면 내 기록의 "오래된 기록" 버튼). 칸의 `aria-label`에 "14일 이상 지난 미해결 기록 N개"가 붙는다.
- **강조**: 지금 주소가 칸의 이동 주소와 같으면(예: `/records?status=resolved`) 그 칸을 연한 색으로 채우고 `aria-current="page"`를 준다. 탭·태그·검색이 붙은 주소에서는 강조하지 않는다.
- **갱신**: 화면을 옮길 때(경로가 바뀔 때), 창으로 다시 돌아왔을 때, 기록이 저장·삭제됐을 때(`records-changed` 알림) 개수를 다시 불러온다. 불러오는 중이거나 처음부터 실패하면 숫자 자리에 "-"를 보이고, 이전 값이 있으면 실패해도 그대로 둔다. 실패해도 화면은 멈추지 않는다.
- 모든 화면(S-001 ~ S-004)의 사이드바에 같게 보인다.

**메뉴 강조 규칙**
- 현재 화면의 메뉴 하나만 강조한다.
- 나머지 메뉴는 기본 모양으로 둔다.
- 메뉴에 해당하지 않는 화면(S-004)에서는 어느 메뉴도 강조하지 않는다.
- S-003(`/records/:id`)에서는 "내 기록" 메뉴를 강조한다. (D-037)
- 강조 모양은 시안을 참고한다.

## 4. 화면별 명세

### S-001 에러 해결 (`/solve`)
| 구분 | 내용 |
|------|------|
| 이번 범위 | 본문 제목 "에러 해결" 표시, 사이드바의 "에러 해결" 메뉴 강조, 탭 3개("에러 입력" / "AI 제안 → 시도 기록" / "결과", D-064), 시리즈 선택, 태그 입력, 에러 메시지, 상황 (선택) 입력, 비슷한 기존 기록(자동 검색), 흐름과 시도 기록·결과 영역(아래) |
| 이후 작성 | 그 밖의 영역은 시안 참고, Q-004 결정 후 작성 (관련: R-001 ~ R-004) |

#### 화면 구성 (탭)
- "에러 입력" 탭: 시리즈 → 태그 → 에러 메시지 → 상황 (선택) → 비슷한 기존 기록 영역(있을 때) → "해당 없음 → AI에게 묻기"(오른쪽 아래, 파란색 버튼, 이 화면의 버튼은 이것 하나). `frontend/src/pages/SolvePage.tsx`
- "AI 제안 → 시도 기록" 탭: 에러 메시지 전체, 화면에 모아 둔 시도 목록("시도 N · 결과" + 무엇을 했나요), AI 제안 카드, 시도 기록 영역. 탭 옆 배지는 "분석 중…" / "완료"(저장 전까지)
- "결과" 탭: 저장 전에는 "아직 저장한 기록이 없어요." 안내만 보인다. 기록을 저장하면 결과 영역(아래)이 보이고 탭 옆 배지가 "저장됨"이 된다
- 탭을 바꿔도 입력·선택한 값은 그대로 남는다.

#### 입력 잠금 (D-034 변경, D-065)
- "해당 없음 → AI에게 묻기"를 누르면(또는 "이 방법 적용"에 성공하면) "에러 입력" 탭의 에러 메시지·상황·시리즈·태그를 잠그고 버튼을 숨긴다. 시도 기록이 그때의 에러 메시지에 대한 것이기 때문이다.
- 위에 안내를 보여준다. 저장 전: "AI에게 물은 에러예요. 아직 저장하지 않았어요. 내용을 바꾸려면 새 에러로 입력해 주세요." 저장 뒤: "저장한 에러예요. 내용을 바꾸려면 새 에러로 입력해 주세요." + "새 에러 입력" 버튼
- "새 에러 입력"은 모든 입력·모아 둔 시도·결과·피드백을 비우고 "에러 입력" 탭으로 돌아간다. 시리즈·태그 목록도 다시 불러와서 방금 만든 시리즈·태그가 보인다. 저장 전에 모아 둔 시도는 버려진다(경고는 없다).

#### 화면 흐름 (D-064, D-065, D-027)
1. 에러 메시지·시리즈·태그를 입력한다. 입력이 멈추고 300ms 뒤 비슷한 기존 기록을 자동으로 찾는다 (A-003, D-040). 저장하지 않고 검색만 한다.
   - 1건 이상이면 비슷한 기록 영역(아래)을 보여준다. "이 방법 적용"을 누르면 2'로 간다.
   - 0건이면 영역을 숨긴다.
   - 검색이 실패하면(서버 꺼짐 등) "비슷한 기록을 확인하지 못했어요." 안내만 보여준다. 버튼은 계속 쓸 수 있다.
2. "해당 없음 → AI에게 묻기"를 누른다. 입력을 잠그고 "AI 제안 → 시도 기록" 탭으로 가서 A-005로 AI 제안을 받는다. **이때 아무것도 저장하지 않는다.**
2'. (비슷한 기록의 "같은 에러예요, 이 방법 적용") A-002로 에러와 시도 1개(`solved`)를 저장하고 "결과" 탭으로 간다. 3~4는 건너뛴다 (D-069).
3. AI 제안 아래에서 "시도 N 기록하기"로 시도를 쓴다 (아래 시도 기록 영역). 시도는 화면에만 모아 둔다.
4. 시도 폼의 버튼에 따라:
   - "기록 저장": 모아 둔 시도 + 이번 시도를 A-002 한 번으로 저장한다(한 트랜잭션, D-065). 성공하면 "결과" 탭으로 가고 A-016으로 AI 피드백을 받는다. 마지막 시도가 해결됨이면 `resolved`, 아니면 `unresolved`다 (D-066).
   - "해결 안 됨 → 다음 방법 제안받기"(해결 안 됨·일부 해결일 때): 이번 시도를 화면 목록에 추가하고, 모아 둔 시도를 붙여 A-005를 다시 부른다(D-027). 새 제안과 "시도 N+1 기록하기"가 나온다. 저장하지 않는다.

- A-002 저장이 실패하면 안내(서버 문구 또는 "에러를 저장하지 못했어요. 잠시 뒤 다시 시도해 주세요.")를 보여주고 입력과 모아 둔 시도를 그대로 둔다. "기록 저장"을 다시 누르면 다시 저장한다.
- 새 시리즈 이름이 비었거나 중복이면 "해당 없음 → AI에게 묻기"를 막고 "시리즈 이름을 확인해 주세요." 안내를 보여준다. 에러 메시지가 비어도 막는다.
- 저장 중에는 버튼이 "저장 중…"으로 바뀌고 다시 누를 수 없다. 빠르게 두 번 눌러도 요청은 한 번만 간다.
- 저장에 성공하면 화면의 모든 입력이 잠긴 채 유지된다. 새로 입력하려면 결과 영역의 "새 에러 입력"을 누른다.

**동작 규칙**
- 입력이 멈추고 300ms 뒤 검색한다. 입력이 바뀌면 이전 요청은 취소하고 늦게 온 응답은 버린다. 새 결과가 올 때까지는 이전 결과를 그대로 두어 목록이 깜빡이지 않게 하고, 그동안 "비슷한 기록을 찾는 중…"을 보여주며 "이 방법 적용"은 비활성이다.
- 에러 메시지를 비우면 영역과 안내가 사라진다.
- "이 방법 적용"을 누르면 A-002로 에러와 시도 1개(`action`은 "기존 기록 #N의 해결 방법 적용", `solved`)와 한 줄 정리(고른 기록의 것을 복사)를 한 번에 저장하고 "결과" 탭을 보여준다 (D-069). 이때 고른 기록의 ID를 `reused_from_id`로 함께 보내 원본과 연결한다 (D-080). 결과 영역에서 피드백을 받고, 한 줄 정리는 바로 수정할 수 있다.
- 적용 중에는 버튼을 비활성하고 누른 카드 버튼이 "적용 중…"으로 바뀐다. 빠르게 두 번 눌러도 한 번만 처리한다.
- 저장이 실패하면 영역 안에 "… 입력한 내용은 그대로 있어요." 안내를 보여준다. 입력은 잠기지 않고, 다시 누르면 다시 저장한다.

- **잠금 표시**: 에러 메시지·상황은 잠긴다. 안내 "미해결 기록을 이어서 해결하고 있어요. 내용을 바꾸려면 새 에러로 입력해 주세요." + "새 에러 입력". 시리즈·태그는 선택·입력 컴포넌트 대신 읽기 전용 칩("시리즈 · 태그")으로 보이고 고칠 수 없다(고치려면 상세의 "태그·시리즈·상황 수정"). 입력은 잠겨 있어도 "해당 없음 → AI에게 묻기"와 "이 방법 적용"은 쓸 수 있다.
- **이전 시도**: "이전 시도 N개" 목록(번호·결과 배지·무엇을 했나요)을 "에러 입력" 탭의 상황 아래와 "AI 제안 → 시도 기록" 탭에 읽기 전용으로 보여준다. 기존 한 줄 정리가 있으면 "기존 한 줄 정리: …"를 함께 보여주고, 시도 폼의 정리를 비워 저장하면 그대로 남는다(시도 폼에 미리 채우지 않는다). 이번에 모으는 시도 번호는 이전 시도 다음부터 센다(보기용, 실제 번호는 서버가 매긴다).
- **AI·저장**: "AI에게 묻기"와 "해결 안 됨 → 다음 방법 제안받기"는 A-005를 부르고 `previous_attempts`에 DB의 기존 실패·일부 해결 시도와 이번에 모은 시도를 함께 넣는다 (D-076). "기록 저장"과 "같은 에러예요, 이 방법 적용"은 A-002가 아니라 A-006으로 이번에 새로 한 시도만 저장한다(적용은 시도 1개 + 고른 기록의 한 줄 정리). 저장하면 결과 탭이 열리고 A-016으로 피드백을 다시 받는다. 같은 기록에 시도가 이어지고 새 기록은 생기지 않는다 (D-077).
- 저장이 실패하면(서버 문구 포함, 이미 해결된 에러면 "이미 해결된 에러예요.") 안내만 보이고 모은 시도는 그대로 남아 다시 저장할 수 있다. 저장 중에는 버튼이 비활성이고 빠르게 두 번 눌러도 요청은 한 번이다.
- "새 에러 입력"은 주소의 `retry`를 지우고 모든 상태를 일반 모드로 초기화한다.

**입력 규칙**
- Enter로 추가한다. 한글 조합 중(`isComposing`)의 Enter는 무시한다. 두 번 들어가거나 글자가 떨어지지 않게 하기 위해서다.
- 입력칸이 비어 있을 때 Backspace를 누르면 마지막 칩을 지운다.
- 이름은 앞뒤 공백 → 앞의 `#` → 다시 앞뒤 공백 순서로 지운다. 결과가 비면 추가하지 않는다. (D-019)
- 이미 추가한 태그와 대소문자만 달라도 같은 태그로 보고 추가하지 않는다. (D-019)
- 기존 태그와 대소문자만 다르면 기존 표기로 바꿔 추가한다. 예: `python` → `Python` (D-019)
- 5개가 찬 상태에서 더 추가하려 하면 추가하지 않고 안내한다. (D-022)
- 자동 완성 목록은 클릭하거나 ↑↓로 고른 뒤 Enter로 추가한다.
- 새 태그는 이 영역에서 저장하지 않는다. 에러를 저장할 때 함께 만든다. (D-020)

#### 오래된 기록 (D-078)
- **무엇이 오래된 기록인가**: 상태가 미해결이고 등록한 지 **14일 이상**(등록 시각부터 14 × 24시간 이상) 지난 기록이다. 해결된 기록은 아무리 오래돼도 아니다. 이어서 해결하기로 시도를 더해도 기준은 등록 시각이다. 서버가 계산한 `is_stale`을 그대로 쓰므로 화면이 날짜를 다시 계산하지 않는다 (API-SPEC_11 A-008, A-017).
- **"오래된 기록" 칩**: 날짜별 탭의 상태 칩 줄에서 "해결만" 바로 옆, 다른 칩과 같은 모양(둥근 칩, 같은 글자 크기·여백, 기록 개수 포함)이다. 눌러 켜면 `?stale=1`이 주소에 붙고 오래된 기록만 보인다. 상태 칩(전체·미해결만·해결만)과 하나만 켜지므로, 이 칩을 켜면 다른 칩이 꺼지고 다른 칩을 누르면 이 칩이 꺼진다. 한 번 더 누르면 꺼져서 "전체"로 돌아간다. 검색·태그 필터와는 함께 쓸 수 있다. 개수는 필터와 상관없는 전체 기록 기준이다(다른 칩과 같음).
- **빨간 불**: 깜빡이는 작은 빨간 원(지름 10px, 1.1초 주기로 흐려졌다 밝아지고 바깥으로 파문이 번진다). 보이는 곳은 세 군데다.
  1. "오래된 기록" 칩 안, 글자 앞. 오래된 기록이 1건 이상일 때만 보인다. 칩이 켜져 빨간 바탕이 되면 불은 흰색으로 바뀐다.
  2. 사이드바 미해결 칸 (3절 "사이드바 통계").
  3. 목록의 오래된 기록 항목마다, 상태 배지와 제목 사이. 날짜별·태그별·시리즈별 탭의 목록이 같은 모양의 항목을 쓰므로 어느 탭에서도 보인다.
- 불은 눈으로만 보이는 표시라 스크린 리더용 이름("등록한 지 14일 이상 지난 미해결 기록" 등)과 마우스를 올렸을 때 설명을 같이 준다. "움직임 줄이기" 설정이면 깜빡이지 않고 고정된 붉은 불로 보인다.
- **빈 결과**: 오래된 기록이 하나도 없으면 "14일 이상 지난 미해결 기록이 없어요." + "필터 지우기"를 보인다(검색·태그를 함께 걸었으면 일반 문구 "조건에 맞는 기록이 없어요.").
- **지우기**: 오래된 기록도 일반 기록과 같다. 항목을 눌러 상세(S-003)에서 "삭제"(확인 창 포함, D-043)로 언제든 지울 수 있다.
- 태그별·시리즈별 탭에는 상태 칩 줄이 없어 "오래된 기록" 칩도 없다(시리즈별 탭의 순서 바꾸기가 시리즈 전체 기준이라서, D-042). 그 탭의 목록 항목에는 빨간 불이 보인다.

#### 재사용 기록 묶기 (D-080, D-081)
- **무엇이 재사용 기록인가**: 비슷한 기록의 "같은 에러예요, 이 방법 적용"으로 저장한 기록이다. 새 기록으로 따로 저장되고, 서버가 맨 처음 원본을 `reused_from_id`로 가리킨다(A-008). 그래서 묶음은 한 단계만 있다.
- **날짜별·태그별 탭**: 받은 목록(A-008 결과) 안에서 원본과 재사용 기록이 함께 있으면 재사용 기록을 원본 아래로 접는다.
  - 원본 줄의 **오른쪽 끝**에 "재사용 N ▾" 배지(파란 칩)가 있다. N은 `reuse_count`(태그·시리즈 필터와 상관없는 전체 수)다. 배지를 누르면 접힌 재사용 기록이 원본 아래에 들여쓰기로 펼쳐지고(▴), 한 번 더 누르면 접힌다. **기본은 접힘**이다. 펼친 기록은 날짜순(오래된 것 먼저)이고 날짜가 함께 보인다. 접힌 기록을 눌러도 상세로 간다.
  - 재사용 기록이 이 결과에 없으면(필터 때문에 안 걸림) 펼칠 것이 없어 배지는 "재사용 N" 표시만 한다(누를 수 없음).
  - 날짜별 탭의 날짜 제목 개수는 접힌 기록을 빼고 줄 수로 센다. 재사용 기록은 원본이 있는 날짜 묶음 아래에 들어간다.
  - 결과에 **재사용 기록만** 있으면(예: 태그 필터에 재사용 기록의 태그만 걸림) 묶지 않고 단독 줄로 보여주고, 줄 오른쪽 끝에 "원본 #N" 링크(회색 칩)를 단다. 링크를 누르면 원본의 상세(S-003)로 간다. 원본이 지워졌으면(`reused_from_id`가 null) 일반 기록처럼 보인다.
  - 묶기는 프론트가 받은 목록 안에서 한다. A-008에는 페이지 나누기가 없다.
- **시리즈별 탭**: 묶지 않는다. 각 기록은 자기 시리즈의 `series_order` 자리에 그대로 두고, 재사용 기록의 제목 줄 오른쪽 끝에 표시용 "재사용" 배지만 붙인다(누를 수 없음).
- 재사용 기록은 입력할 때 정한 태그·시리즈를 따로 가진다. 원본을 고쳐도 재사용 기록은 바뀌지 않는다.

#### 탭: 날짜별 / 태그별 / 시리즈별 (D-042, D-055)
- 제목 아래에 가로로 꽉 찬 탭 3개 "날짜별"(기본) / "태그별" / "시리즈별"을 둔다. 고른 탭은 어두운 바탕으로 보인다(시안 참고). 고른 탭은 주소 쿼리 `?view=tag` / `?view=series`에 둔다(없으면 날짜별). 주소로 열거나 상세에 갔다 뒤로 와도 같은 탭이 남는다.
- 목록 항목은 모든 탭이 같은 모양이다(시안 참고): 윗줄에 상태 배지 + 제목, 아랫줄에 시리즈(주황 칩, 시리즈별 탭에서는 숨김)·날짜(날짜 제목이 없는 태그별·시리즈별 탭에서만 "10/30")·시도 N회·태그 칩.
- "날짜별" 탭은 위에서 설명한 목록과 필터 그대로다. 단, 상태 칩(전체 / 미해결만 / 해결만 / 오래된 기록)과 태그 칩 옆에 기록 개수를 보여준다(시안 ①). 개수는 필터와 상관없는 전체 기록 기준이다. 개수를 불러오지 못하면 개수만 숨기고 칩은 그대로 쓴다.
- "태그별" 탭 (D-055, 시안 ②): 검색창·상태 칩은 숨긴다. "태그 N개 · 많이 쓴 순"(같은 줄 오른쪽에 "⚙ 태그 관리" 버튼, 태그가 0개면 숨김, D-063) 아래에 태그 칩(이름 + 그 태그의 기록 수 `error_count`, 많이 쓴 순·같으면 이름순)을 보여주고, 칩을 누르면 켜지고 꺼진다. 고른 태그는 날짜별 탭과 같은 `tag_id`를 쓴다. 아래에 "#Python + #패키지 기록 N개" 제목과 날짜 제목 없는 한 줄 목록(최근 등록 순)을 보여준다. 여러 개를 고르면 모두 가진 기록만 보인다. 고른 태그가 없으면 "위에서 태그를 눌러 기록을 모아 보세요.", 결과가 없으면 "고른 태그를 모두 가진 기록이 없어요.". 태그가 하나도 없으면 "아직 태그가 없어요."
- "시리즈별" 탭에서는 검색창과 상태·태그 칩을 숨긴다. 순서 바꾸기(A-014)가 그 시리즈의 에러 **전체**를 대상으로 하므로, 필터로 일부만 보이면 ▲▼의 뜻이 모호해지기 때문이다.
- 제목 줄에는 "내 기록"만 둔다. "⚙ 관리" 버튼은 없다(D-062). 태그 관리는 태그별 탭에서, 시리즈 만들기·수정·삭제는 시리즈별 탭에서 한다. 메뉴는 늘리지 않는다(D-005).
- 탭을 바꾸는 것은 방문 기록에 남기지 않는다(주소를 바꿔 끼움). 시리즈를 열고 닫는 것은 방문 기록에 남겨서 브라우저 뒤로 가기가 이전에 연 시리즈(또는 카드만 보이는 상태)로 돌아간다.
- 날짜별 탭으로 돌아오면 목록을 다시 불러온다. 태그 관리 모달에서 바뀐 게 있으면 닫을 때 태그 칩과 기록 목록을 다시 불러온다.

#### 시리즈별 보기 (D-042, D-051, D-053)
1. **시리즈 카드** (`?view=series`): 시리즈마다 카드 하나 — 이름, "에러 N개"(`error_count`, A-004). 최근 만든 시리즈가 위. 카드는 시리즈를 열어도 항상 위에 보이고, 연 시리즈의 카드는 강조된다(시안 ③). 카드를 누르면 그 시리즈를 연다. 아무것도 열지 않았으면 카드 아래에 "시리즈를 눌러 같은 주제의 에러를 순서대로 보세요." 시리즈가 하나도 없으면 "아직 시리즈가 없어요. 새 시리즈를 만들거나, 에러를 입력할 때 만들 수 있어요." + "+ 새 시리즈" 버튼. 아무것도 열지 않았을 때의 안내 옆에도 "+ 새 시리즈" 버튼이 있다
2. **고른 시리즈** (`?view=series&series_id=N`): 카드 아래에 보인다.
   - 시리즈 이름·설명, 이름 오른쪽에 "+ 새 시리즈" 버튼(시안 ③)
   - 맨 아래에 "시리즈 지정 방법" 안내 상자(고정 문구: 시리즈별 탭에서 새로 만들기 / 에러 해결 창에서 고르거나 새로 만들기 / 에러 일기 상세에서 나중에 지정·변경·해제 / 에러 하나는 시리즈 하나에만 속하고 지정하면 마지막 순서로 추가)
   - 에러 목록(A-008 `series_id`, 시리즈 안 순서): 항목마다 순서 번호(목록 위치 1부터, D-051), 상태 배지, 제목(첫 줄), 재사용 기록이면 표시용 "재사용" 배지(제목 줄 오른쪽 끝, D-081), 시도 N회, 태그, ▲ ▼ 버튼. 항목을 누르면 S-003으로 간다(▲▼는 눌러도 이동하지 않는다)
   - 시리즈가 없는 에러는 시리즈별 탭에 나오지 않는다 (D-053)
   - 에러 목록 아래에 "시리즈 이름·설명 수정"과 "시리즈 삭제" 버튼(시안 ③, D-062)
3. **순서 바꾸기**: ▲는 한 칸 위, ▼는 한 칸 아래로 옮긴다. 첫 항목의 ▲, 마지막 항목의 ▼는 비활성이다. 누르면 화면을 먼저 바꾸고 전체 순서를 A-014로 보낸다. 저장 중에는 ▲▼를 모두 비활성으로 두고, 실패하면 원래 순서로 되돌린 뒤 "순서를 바꾸지 못했어요. 다시 시도해 주세요."를 보여준다.
4. **이름·설명 수정**: 이름 입력칸과 설명 입력칸(설명은 비워도 됨)이 열리고 "저장" / "취소"가 있다. 저장하면 A-013 `PATCH`. 같은 이름이 이미 있으면(409) "이미 있는 이름이에요."를 보여주고 입력값은 그대로 둔다. 이름이 비면 저장 버튼을 막는다 (D-054). 폼은 에러 목록 아래의 버튼 자리에 열린다.
5. **새 시리즈** (D-061): "+ 새 시리즈"를 누르면 카드 아래에 이름(필수)·설명(선택) 입력칸과 "만들기" / "취소"가 열린다. 만들면 A-015 `POST`, 성공하면 시리즈 목록을 다시 받고 새 시리즈를 연다(`?view=series&series_id=새 ID`). 같은 이름이면(409) "이미 있는 이름이에요."를 보여주고 입력값은 그대로 둔다. 서버 오류도 안내만 하고 입력값을 둔다. 이름이 비면 만들기 버튼을 막고, 빠르게 두 번 눌러도 요청은 한 번만 보낸다.
6. **시리즈 삭제** (D-050, D-062): 확인 창 "'개발 환경' 시리즈를 지울까요? 3개 기록에서 시리즈가 비워져요. 기록은 지워지지 않아요." (개수가 0이면 "되돌릴 수 없어요."만). 확인하면 A-013 `DELETE`, 성공하면 시리즈 선택을 닫고(주소의 `series_id` 제거) 카드 목록을 다시 받는다. 이미 지워진 시리즈(404)면 "이미 삭제된 항목이에요."를 카드 위에 보여주고 같은 방식으로 정리한다. 그 밖의 실패는 확인 창을 열어 둔 채 안내만 바꾸고 다시 시도할 수 있다.

| 상태 | 화면 |
|------|------|
| 시리즈 목록 불러오는 중 / 실패 | "불러오는 중…" / "시리즈를 불러오지 못했어요." + "다시 시도" |
| 고른 시리즈의 에러 불러오는 중 / 실패 | "불러오는 중…" / "기록을 불러오지 못했어요." + "다시 시도" |
| 고른 시리즈에 에러가 0개 | "이 시리즈에 속한 기록이 없어요." |
| 없는 시리즈 ID(주소에 남은 예전 ID, 삭제된 시리즈) | 카드 아래에 "시리즈를 찾을 수 없어요." + "선택 닫기" |
| 이름·설명 저장 중 / 실패 | 버튼 비활성 "저장 중…" / 입력값 유지 + 안내 + 다시 시도 |
| 새 시리즈 만드는 중 / 실패 | 버튼 비활성 "만드는 중…" / 입력값 유지 + 안내(같은 이름 409 "이미 있는 이름이에요.") |
| 시리즈 삭제 중 / 실패 / 이미 삭제됨(404) | 확인 창 버튼 비활성 "삭제 중…" / 확인 창 유지 + 안내 / 선택 닫기 + 카드 위 "이미 삭제된 항목이에요." |
| 순서 저장 실패 | 원래 순서로 되돌리고 안내. 화면의 기록이 서버와 어긋난 경우(422)에는 서버 안내를 보여주고 목록을 다시 불러온다. 이미 지워진 시리즈(404)는 "시리즈를 찾을 수 없어요." |

#### 태그 관리 모달 (D-063, D-049, D-050)
- 태그별 탭의 "⚙ 태그 관리"(캡션 줄 오른쪽, 태그가 0개면 숨김)를 누르면 태그만 다루는 모달이 열린다. 닫기(×, 바깥 클릭, Esc)를 누르면 닫히고, 닫을 때 바뀐 게 있으면 태그 칩과 기록 목록을 다시 불러온다. 지운 태그가 태그 필터(주소의 `tag_id`)에 걸려 있었다면 주소의 필터에서도 뺀다(없는 태그로 거르면 항상 빈 결과라서).
- 구성: 태그마다 이름, "N개 기록"(`error_count`, A-004), "이름 변경", "삭제". 이름순(A-004와 같다).
- **이름 변경**: 그 줄이 입력칸 + "저장" / "취소"로 바뀐다. 저장하면 A-012 `PATCH`. 같은 이름이 이미 있으면(409) "이미 있는 이름이에요."를 그 줄에 보여주고 입력값은 그대로 둔다. 같은 태그의 대소문자만 바꾸는 것은 허용한다 (D-049). 저장하면 서버의 이름순으로 다시 받아 정렬이 바뀔 수 있다. 입력 중 Esc는 모달이 아니라 그 줄의 수정만 닫는다. 이름 입력칸에 글자 수 제한은 두지 않는다(최대 길이는 Later).
- **삭제**: 확인 창 "#Python 태그를 지울까요? 3개 기록에서 태그가 빠져요. 기록은 지워지지 않아요." 개수가 0이면 "되돌릴 수 없어요."만 보여준다. 확인하면 A-012 `DELETE`. 쓰이는 태그도 지울 수 있다 (D-050).
- 태그를 새로 만드는 곳은 여기에 없다. 에러를 입력할 때 만든다 (D-020). 시리즈는 이 모달에서 다루지 않는다(시리즈별 탭, D-062).

| 상태 | 화면 |
|------|------|
| 목록 불러오는 중 / 실패 | "불러오는 중…" / "불러오지 못했어요." + "다시 시도" |
| 태그가 0개 | "아직 태그가 없어요." (버튼은 숨겨지지만, 모달을 연 채 다른 곳에서 지워진 경우) |
| 저장·삭제 중 | 그 줄의 버튼 비활성, "저장 중…" / "삭제 중…" |
| 이름 충돌 (409) | "이미 있는 이름이에요." 입력값 유지 |
| 이미 삭제됨 (404) | 모달 위쪽에 안내 "이미 삭제된 항목이에요."를 보여주고 목록을 다시 불러와 줄이 사라진다(삭제 확인 창은 닫는다) |
| 그 밖의 실패 | 입력값 유지 + 안내 + 다시 시도 |

**구성** (위에서 아래로)
1. "← 내 기록": 들어오기 전 목록(필터 포함)으로 돌아간다. 주소로 바로 들어온 경우에는 `/records`로 간다
2. 화면 제목 "에러 일기"
3. 상태 배지 + 제목(에러 메시지 첫 줄), 그 아래 "10월 28일 14:05 등록", 시리즈, 태그
4. 에러 메시지 전체, 상황(있을 때만)
5. 시도 기록 타임라인(시안 ④): 세로선 위에 점으로 이어진다. 처음은 "M월 D일 HH:MM · 에러 발생" + 에러 메시지 첫 줄(빨간 점), 이어서 시도 번호 순서로 "시각 · 시도 N" + 결과 배지(해결됨 / 해결 안 됨 / 일부 해결, 에러 해결 화면과 같은 문구, D-028) + 무엇을 했나요. 점 색은 결과를 따른다(해결됨 초록, 일부 해결 주황, 해결 안 됨 빨강). 시도 출처 표시(AI 제안 등)는 D-032 Later라 넣지 않는다
   - **재사용 기록이 있는 원본** (v11, D-081): 타임라인에 이 기록을 재사용한 기록(A-009 `reuses`)이 시도와 **날짜순으로 합쳐져** 들어간다. 항목마다 "시각 · 이 방법을 다시 적용했어요", 그 기록의 상황(있으면), 그 기록의 시리즈·태그 칩, "기록 #N 보기" 링크(그 기록의 상세로 이동)가 있다. 점은 파란색이다.
   - **재사용 기록** (v11, D-080): 시도 문구 "기존 기록 #N의 해결 방법 적용"에서 "기존 기록 #N"이 **원본 상세로 가는 링크**다(링크의 번호는 맨 처음 원본의 번호). 원본이 지워졌으면 문구만 보인다. 시도 문구 자체는 그대로 남는다
6. 내 한 줄 정리 (있으면 상태와 상관없이 보인다, D-067)
7. ✨ AI 피드백 칸 (정리가 없어도 칸은 있다, 아래 "한 줄 정리·AI 피드백")

- 주소의 ID가 숫자가 아니면 서버에 묻지 않고 "기록을 찾을 수 없어요."를 보여준다.

#### 수정 (D-047, D-048)
- 상세 제목 줄 아래에 (미해결이면 "이어서 해결하기", 아래 절) "태그·시리즈·상황 수정", "한 줄 정리 수정"(정리가 없으면 "한 줄 정리 쓰기"), "삭제" 버튼이 있고, 맨 오른쪽 끝에 "Markdown 내려받기"·"PDF로 인쇄"가 있다(아래 "내보내기").
- "태그·시리즈·상황 수정"을 누르면 같은 화면이 **편집 모드**로 바뀐다. 시리즈 선택(`SeriesSelect`), 태그 입력(`TagInput`), 상황 입력칸이 현재 값으로 채워져 나타나고 "저장" / "취소"가 있다. 두 컴포넌트는 에러 해결 화면과 같은 것을 재사용하고, 현재 값을 채우는 선택 props만 더한다(기존 사용법은 그대로).
- 에러 메시지, 상태, 시도 기록, 내 한 줄 정리는 편집 모드에서도 읽기 전용이다. 에러 메시지는 비슷한 기록 검색의 기준이라 수정하지 않는다 (D-047). 한 줄 정리 수정은 별도 버튼(아래 "한 줄 정리·AI 피드백")이 맡는다. AI 피드백 칸도 편집 모드에서 읽기 전용이다.
- 규칙은 에러 등록과 같다: 새 시리즈는 이름만 입력하면 저장할 때 만들어지고, 같은 이름이면 기존 시리즈를 쓴다. 태그는 최대 5개, 정규화·기존 표기로 합침, 새 태그는 저장할 때 만들어진다 (D-048). 새 시리즈 이름이 비었거나 중복이면 저장 버튼을 막는다(`SeriesSelect`가 null을 넘기는 상태).
- 저장하면 A-010 `PATCH`로 바뀐 필드만 보내고, 성공하면 편집 모드를 닫고 바뀐 내용을 보여준다. 다른 시리즈로 옮기면 서버가 그 시리즈의 마지막 순서로 넣는다.
- "취소"는 바꾼 것을 버리고 읽기 모드로 돌아간다. 바꾼 게 없으면 "저장"은 비활성이다.
- 편집 모드는 제목 줄 아래 버튼 영역에 폼으로 나타나고(`RecordEditForm.tsx`), 손댄 항목만 서버로 보낸다. 저장 중에는 입력과 버튼이 잠기고 빠르게 두 번 눌러도 요청은 한 번이다.

#### 한 줄 정리·AI 피드백 (D-068, D-070, D-073)
- 담당 팀원 1 (`ErrorDetail.tsx`, `RecordDetailPage.tsx`). 피드백 칸·정리 수정 폼·받기 상태는 팀원 2 폴더 `frontend/src/features/solve/`의 `FeedbackBox.tsx`·`SummaryEditForm.tsx`·`useFeedback.ts`를 가져다 쓴다(에러 해결 화면 결과 탭과 같은 것).
- **한 줄 정리 수정**: 버튼을 누르면 버튼 줄이 입력칸 + "저장" / "취소"로 바뀐다. 저장은 A-007. 성공하면 상세의 정리를 바꾸고 A-016으로 피드백을 다시 받아 덮어쓴다. 해결된 기록은 비워서 저장할 수 없다. 실패하면 입력값을 그대로 두고 안내한다.
- 기록 수정(편집 모드)과 한 줄 정리 수정은 동시에 열지 않는다. 둘 다 열리는 동안 버튼 줄(태그·시리즈·상황 수정 / 한 줄 정리 수정 / 삭제 / 내보내기)은 숨기고 해당 폼만 보인다. 저장·취소하면 버튼 줄이 다시 나타난다.
- **✨ AI 피드백 칸**: "내 한 줄 정리" 아래에 있다(시안 ④). 모양과 동작은 결과 탭과 같다.

| 상태 | 화면 |
|------|------|
| 피드백 있음 | 피드백 문장 |
| 피드백 없음(이전 기록, 받기 실패)이고 시도 또는 한 줄 정리가 있음 | "아직 AI 피드백이 없어요." + "피드백 받기" 버튼 |
| 피드백 없음이고 시도도 한 줄 정리도 없음 | 버튼 없이 "시도 기록이 없어 피드백을 받을 수 없어요."만 |
| 받는 중 | "✨ 피드백을 받는 중이에요…" |
| 받기 실패 | "피드백을 가져오지 못했어요." + "다시 받기" |

#### 이어서 해결하기 버튼 (D-075)
- 상태가 미해결(`unresolved`)인 기록에서만 버튼 줄 맨 앞에 파란 "이어서 해결하기" 버튼이 보인다. 해결된 기록에는 없다.
- 누르면 `/solve?retry={id}`로 이동해 에러 해결 화면(S-001)의 이어서 해결하기로 들어간다. 시리즈·태그·상황 수정, 한 줄 정리 수정이 열려 있으면 버튼 줄과 함께 숨는다.
- 내 기록 목록(S-002) 항목에서 바로 이어서 해결하기로 가는 것은 이번 범위에 없다 (Later 후보).

#### 내보내기 (D-079)
- 담당 팀원 1. 내용·파일 이름은 `frontend/src/features/records/exportMarkdown.ts`의 순수 함수 `toMarkdown(detail)`·`exportFileName(detail, ext)`, 내려받기·인쇄는 `exportActions.ts`, 인쇄용 CSS는 `records.css`, 버튼은 `RecordDetailPage.tsx`다. **새 API·새 패키지는 없다.** 내용은 화면이 이미 불러온 상세(A-009 응답)로 만들고 A-009를 다시 부르지 않는다. 저장하지 않은 편집 값(기록 수정·한 줄 정리 수정 중인 값)은 내보내지 않는다.
- **버튼**: 버튼 줄의 오른쪽 끝에 "Markdown 내려받기"와 "PDF로 인쇄" 두 개가 있다. 상태(해결·미해결)와 상관없이 보인다.

| 상태 | 화면 |
|------|------|
| 불러오는 중 / 없는 ID / 불러오기 실패 / 이미 삭제된 기록 | 버튼이 없다 (버튼 줄 자체가 그려지지 않는다) |
| 기록 수정·한 줄 정리 수정 중 | 버튼 줄이 폼으로 바뀌어 같이 숨는다 |
| 삭제 중 | 내보내기 버튼을 숨긴다 |
| 내려받기·인쇄 실패(예외) | 버튼 줄 아래에 "내보내지 못했어요. 다시 시도해 주세요."를 보여준다. 다시 누르면 다시 시도하고, 성공하면 사라진다. 다른 기록으로 옮기면 따라가지 않는다 |

**Markdown 내용 순서** (시안 ④와 화면 순서를 따른다. 값이 없는 항목은 칸째로 뺀다)
1. 제목 `# {에러 메시지 첫 줄}` (80자를 넘으면 "…"로 자른다)
2. 정보 목록: 상태(해결·미해결), 시리즈와 시리즈 안 순서("개발 환경 (2번째)", 저장된 `series_order` 값이라 중간 기록을 지우면 번호에 빈 곳이 생길 수 있다, D-051), 태그("#Python #가상환경"), 기록한 날짜, 해결한 날짜(해결된 기록만)
3. `## 에러 메시지`: 전체 메시지를 코드 블록으로 넣는다. 펜스는 메시지 안의 가장 긴 백틱 묶음보다 하나 더 길게(최소 3개) 해서 중간에 끊기지 않게 한다
4. `## 상황`
5. `## 시도 기록`: `seq` 순서로 `### 시도 N · 결과`(에러 해결 화면과 같은 결과 문구, D-028) 아래에 시각과 무엇을 했는지
6. `## 내 한 줄 정리`
7. `## AI 피드백`
8. 맨 아래 `---` 뒤에 "에러 일기에서 내보냄 · 2026-11-03 10:00" (한국 시간 기준)

- 날짜는 "2026-10-27 14:05"처럼 보여준다. 화면의 날짜 표시(`10월 28일 14:17`)는 연도가 없어 쓰지 않고 내보내기용 형식을 따로 둔다.
- 상황·시도·한 줄 정리·피드백은 사용자가 쓴 글이라 Markdown 문법 문자를 이스케이프하지 않고 그대로 둔다(사용자가 일부러 쓴 Markdown이 살아난다. 줄 맨 앞의 `#`·`-`·`>`가 제목·목록·인용으로 보일 수 있는 것은 한계다). 이어지는 줄은 미리보기에서 한 줄로 합쳐지지 않게 줄 끝에 공백 두 개를 붙인다.
- 파일 이름은 `error-diary-{id}-{정리한 제목}.md`다. `: / \ * ? " < >` `|`와 작은따옴표·공백·줄바꿈은 `-`로 바꾸고 연속된 `-`는 하나로 줄이며 제목 부분은 50자 이내로 자른다. 제목이 비면 `error-diary-{id}.md`다.
- 내려받기는 UTF-8(BOM 없음) 파일로 만들어 브라우저 다운로드로 내려받는다.

**PDF(인쇄)**
- 누르면 `body`에 `printing-record` 클래스를 붙이고 탭 제목을 파일 이름(`error-diary-{id}-{제목}`, 확장자 없음)으로 잠시 바꾼 뒤 `window.print()`를 부른다. 사용자가 인쇄 대화상자에서 "PDF로 저장"을 고른다. 인쇄를 마치거나 취소하면(`afterprint`) 클래스와 탭 제목을 원래대로 되돌린다. 인쇄 대화상자가 열려 있는 동안 다시 눌러도 한 번만 처리한다.
- 많은 브라우저가 탭 제목을 PDF 기본 파일 이름으로 쓰지만 브라우저마다 다를 수 있다.
- 인쇄에 나오는 것: 화면 제목 "에러 일기", 상태 배지·제목, 등록 시각·시리즈·태그(테두리 칩), 에러 메시지(흰 바탕·검은 글씨, 긴 줄은 줄바꿈), 상황, 시도 기록 타임라인(점 색 유지), 내 한 줄 정리, AI 피드백. 시도 하나·한 줄 정리·피드백 칸은 페이지 사이에서 끊기지 않고, 소제목은 다음 내용과 떨어지지 않는다.
- 인쇄에서 빠지는 것: 사이드바, "← 내 기록", 버튼 줄 전체, 상세 안의 모든 버튼(피드백 받기·다시 받기 등), 확인 창.
- 인쇄용 규칙은 모두 `@media print`와 `body.printing-record` 안에만 있어서, 다른 화면(에러 해결, 내 기록 목록)에서 Ctrl+P를 눌러도 사이드바가 평소처럼 보인다.
- 이번 범위에서 뺀 것: `.docx`·여러 기록 한 번에 내보내기(Later), 용지 여백 지정(`@page`는 다른 화면의 인쇄에도 영향을 줘서 브라우저 기본값을 쓴다), `print()`가 바로 돌아오는 브라우저(일부 모바일 Safari)에서의 복원 보장.

#### 삭제 (D-043, D-044)
- "삭제"를 누르면 확인 창이 뜬다: "이 기록을 지울까요?" + 지워지는 것만 이름을 붙인 안내 — "시도 2개와 한 줄 정리도 함께 지워지고 되돌릴 수 없어요."(시도가 없으면 "시도" 부분, 한 줄 정리가 없으면 "한 줄 정리" 부분을 뺀다. 둘 다 없으면 "되돌릴 수 없어요.") + "취소" / "삭제". 처음 포커스는 "취소"에 있고 Esc로도 닫힌다. 확인 창은 브라우저 기본 모달(`<dialog>`)이다.
- "삭제"를 누르면 A-011 `DELETE`. 성공하면 들어온 목록 주소(`backTo`, 없으면 `/records`)로 이동한다. 실패하면 확인 창을 닫지 않고 안내를 보여주며 확인 버튼이 "다시 시도"로 바뀐다.
- 쓰이지 않게 된 태그·시리즈는 남는다. 지우려면 내 기록의 태그별 탭 "⚙ 태그 관리", 시리즈별 탭의 "시리즈 삭제"에서 한다 (D-046, D-062).

**화면 상태 (수정·삭제)**
| 상태 | 화면 |
|------|------|
| 저장 중 / 삭제 중 | 버튼 비활성, "저장 중…" / "삭제 중…". 빠르게 두 번 눌러도 한 번만 보낸다 |

| 삭제 실패 | 확인 창을 닫지 않고 안내 + "다시 시도" |
| 404 (다른 곳에서 이미 삭제) | "이미 삭제된 기록이에요." + "내 기록으로" |

## 5. 화면 이동 규칙

| 상황 | 동작 |
|------|------|
| 메뉴 클릭 | 해당 화면 경로로 이동하고, 메뉴 강조를 그 화면으로 바꾼다 |
| 현재 화면의 메뉴 다시 클릭 | 화면을 그대로 둔다 |
| 처음 접속 (`/`) | S-001 에러 해결(`/solve`)로 이동한다 |
| 없는 경로 접근 | S-004 "찾을 수 없음" 안내를 보여준다. 사용자는 사이드바 메뉴로 다른 화면에 갈 수 있다 |
| 내 기록 항목 클릭 | S-003 `/records/:id`로 이동한다. "내 기록" 메뉴 강조는 그대로다 |
| 상세에서 "← 내 기록" / 브라우저 뒤로 가기 | 들어오기 전 목록 URL(필터 포함)로 돌아간다 |
| 상세에서 삭제 성공 | 들어온 목록 URL(필터·탭 포함)로 이동한다. 삭제한 상세 주소는 방문 기록에서 바꿔 끼운다 |
| "태그별" 탭 / 태그 칩 | `?view=tag` / `?view=tag&tag_id=N…`로 바뀐다 (D-055) |
| "시리즈별" 탭 / 시리즈 카드 | `?view=series` / `?view=series&series_id=N`로 바뀐다. 브라우저 뒤로 가기는 이전에 연 시리즈 또는 카드만 보이는 상태로 돌아간다 |
