### S-001 에러 해결 (`/solve`)
| 구분 | 내용 |
|------|------|

#### 화면 구성 (탭)
- "에러 입력" 탭: 시리즈 → 태그 → 에러 메시지 → 상황 (선택) → "해결 방법 찾기". `frontend/src/pages/SolvePage.tsx`
- "AI 분석" 탭: 저장된 에러 메시지, 저장한 시도 목록("시도 N · 결과" + 무엇을 했나요), AI 제안 카드, 시도 기록 영역 또는 해결 완료 영역. 탭 옆 배지는 "분석 중…" / "완료"
- 탭을 바꿔도 입력·선택한 값은 그대로 남는다.

#### 에러 저장 후 잠금 (D-034)
- A-002로 저장되면 "에러 입력" 탭의 에러 메시지·상황·시리즈·태그를 잠그고 "해결 방법 찾기" 버튼을 숨긴다.
- 위에 "저장된 에러예요. 내용을 바꾸려면 새 에러로 입력해 주세요." 안내와 "새 에러 입력" 버튼을 보여준다.
- "새 에러 입력"은 모든 입력과 결과를 비우고 "에러 입력" 탭으로 돌아간다. 시리즈·태그 목록도 다시 불러와서 방금 만든 시리즈·태그가 보인다.

#### 화면 흐름 (D-025, D-027)
1. 에러 메시지·시리즈·태그를 입력하고 "해결 방법 찾기"를 누른다.
2. 비슷한 기존 기록을 확인한다 (A-003, 미구현). "해당 없음 → AI에게 묻기"를 누르거나 비슷한 기록이 0건이면 3으로 간다.
   - A-003이 생기기 전까지는 항상 0건으로 보고 바로 3으로 간다.
3. A-002로 에러를 미해결 상태로 저장한다. 성공하면 A-005로 AI 제안을 받는다.
4. AI 제안 아래에서 "시도 N 기록하기"로 시도를 기록한다 (아래 시도 기록 영역).
5. "해결됨"이면 해결 완료 영역으로, "해결 안 됨"·"일부 해결"이면 새 AI 제안과 "시도 N+1 기록하기"로 돌아간다.

- A-002 저장이 실패하면 AI로 넘어가지 않고 입력값을 그대로 둔 채 안내("… 입력한 내용은 그대로 있어요.")를 보여준다. "해결 방법 찾기"를 다시 누르면 다시 시도한다. 시도는 `error_id`가 있어야 저장되기 때문이다.
- 새 시리즈 이름이 비었거나 중복이면 "해결 방법 찾기"를 막고 "시리즈 이름을 확인해 주세요." 안내를 보여준다.
- 저장 중에는 버튼이 "저장 중…"으로 바뀌고 다시 누를 수 없다.

**입력 규칙**
- Enter로 추가한다. 한글 조합 중(`isComposing`)의 Enter는 무시한다. 두 번 들어가거나 글자가 떨어지지 않게 하기 위해서다.
- 입력칸이 비어 있을 때 Backspace를 누르면 마지막 칩을 지운다.
- 이름은 앞뒤 공백 → 앞의 `#` → 다시 앞뒤 공백 순서로 지운다. 결과가 비면 추가하지 않는다. (D-019)
- 이미 추가한 태그와 대소문자만 달라도 같은 태그로 보고 추가하지 않는다. (D-019)
- 기존 태그와 대소문자만 다르면 기존 표기로 바꿔 추가한다. 예: `python` → `Python` (D-019)
- 5개가 찬 상태에서 더 추가하려 하면 추가하지 않고 안내한다. (D-022)
- 자동 완성 목록은 클릭하거나 ↑↓로 고른 뒤 Enter로 추가한다.
- 새 태그는 이 영역에서 저장하지 않는다. 에러를 저장할 때 함께 만든다. (D-020)

| 6번째 태그를 추가하려 함 | 추가하지 않음 | - | "태그는 최대 5개까지 넣을 수 있어요." (오류 색) |

- API 실패·로딩 중에도 다른 입력(시리즈, 에러 메시지 등)은 그대로 쓸 수 있다.

### S-002 내 기록 (`/records`)
| 구분 | 내용 |
|------|------|
| 이번 범위 | 날짜별 목록, 검색, 상태 필터, 태그 필터 (D-035). 목록은 A-008, 태그 칩은 A-004 `GET /api/tags` |
| 이후 작성 | 시리즈별 보기, "재사용 N" 배지, 필터 칩 개수, 사이드바 통계 (PRD Q-004 "이후 단계") |
| 담당 | 팀원 1 (`frontend/src/pages/RecordsPage.tsx`, `frontend/src/features/records/RecordFilters.tsx`·`RecordList.tsx`·`records.css`, D-039) |

**구성** (위에서 아래로)
1. 제목 "내 기록"
2. 검색창: 안내 문구 "에러 메시지 검색"
3. 상태 칩: 전체 / 미해결만 / 해결만 (하나만 선택, 기본 "전체")
4. 태그 칩: 기존 태그 전체(이름순), 여러 개 선택. 아래 안내 "태그를 여러 개 누르면 모두 포함한 기록만 보여요"
5. 날짜별 목록
   - 날짜 제목: "10월 30일 (목)" + 그날 개수. 날짜는 `created_at`의 날짜 부분으로 묶는다. 최근 날짜가 위
   - 항목: 상태 배지("미해결" / "해결", D-028), 제목(에러 메시지 첫 줄), 시리즈 이름, "시도 N회", 태그
   - 항목을 누르면 S-003(`/records/:id`)으로 간다

**필터 규칙**
- 검색·상태·태그는 모두 서버에서 거른다 (A-008, D-036). 셋을 함께 쓰면 모두 만족하는 기록만 보인다.
- 필터 값은 URL 쿼리에 둔다. 상세에 갔다가 뒤로 오거나, 같은 주소로 다시 열면 필터가 그대로다 (D-036).
- 검색은 입력이 멈추고 잠시(0.3초) 뒤에 주소에 반영하고 요청한다. 검색어를 빠르게 바꿔도 마지막 검색어의 결과만 보인다(이전 요청은 취소). 반영 전에 항목을 누르면 반영 전 목록 주소로 돌아온다.
- 태그를 여러 개 고르면 고른 태그를 모두 가진 기록만 보인다.
- 필터를 바꿔도 방문 기록이 쌓이지 않는다(주소를 바꿔 끼움). 브라우저 뒤로 가기는 내 기록에 들어오기 전 화면으로 간다.
- 주소에 없는 태그 ID가 있으면 "조건에 맞는 기록이 없어요."를 보여준다(A-008 빈 결과).

**화면 상태**

| 상태 | 화면 |
|------|------|
| 불러오는 중 | 목록 자리에 "불러오는 중…". 필터는 계속 쓸 수 있다 |
| 기록 0개 (필터 없음) | "아직 기록이 없어요. 에러 해결에서 첫 에러를 입력해 보세요." + "에러 해결로" 버튼 |
| 필터 결과 0개 | "조건에 맞는 기록이 없어요." + "필터 지우기" |
| 목록 불러오기 실패 | "기록을 불러오지 못했어요." + "다시 시도". 필터 값은 그대로 |
| 태그 목록 실패 | 태그 칩 자리에만 "태그를 불러오지 못했어요." + "다시 시도". 검색·상태 필터는 그대로 쓸 수 있다 |

- 주소의 ID가 숫자가 아니면 서버에 묻지 않고 "기록을 찾을 수 없어요."를 보여준다.
